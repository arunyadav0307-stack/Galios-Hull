## 1. Why this was worth doing

Every quantitative claim in this project is a number in a log file. Those logs were written by
successive versions of the scripts across ~20 commits, and several of the scripts were rewritten
mid-project (the numpy-free rewrite of `dist_of_span` in P3-1; the two bug fixes in P3-7; the
`basis × basis` fix in P3-5). Until now nothing established that *the scripts as committed still
produce the logs as committed*. That is a different question from "were the numbers right when they
were computed", and it is the one that matters to anyone who clones this repository and re-runs it.

## 2. What is compared

For each of the 14 probes the script is re-executed from the repository root with
`PYTHONHASHSEED=0`, its stdout captured, and compared line-by-line with the committed log. Exit code
must be 0. **836 log lines are compared in total** (out of 893 stored; the difference is accounted for
exactly by the normalisation below).

Normalisation is deliberately narrow, and every rule corresponds to text that the *logging command*
wrote rather than the script:

| Rule | What it removes | Why it is not a claim |
|---|---|---|
| elapsed-time lines | `[elapsed 760.7s]` | wall-clock, machine-dependent |
| banner | `# P3-3 ring-level Gray coupling log -- generated 2026-10-24T00:09:08Z` | added by the shell when logging |
| interpreter line | `Python 3.11.2` | same |
| part headers | `## 1. r1_probe.py -- field level: ...` | see §3 |
| legacy failure line | `numpy: ModuleNotFoundError: No module named 'numpy'` | see §4 |
| trailing CSV dump | everything after `## csv head` | the CSV is checked byte-for-byte instead |

Nothing else is tolerated. A changed digit in any number fails the comparison, and the failure
message prints the first differing line with both versions.

## 3. Finding: three phase-2 logs are composites

`r1_probe_log.txt`, `r2_probe_log.txt` and `r3_probe_log.txt` each contain the output of more than
one script, separated by `## <script>.py -- <description>` headers. The tool now models each log as a
list of parts and compares the *concatenation*:

| Log | Parts |
|---|---|
| `r1_probe_log.txt` | `r1_probe.py`, `r1_orbit_check.py` |
| `r2_probe_log.txt` | `r2_probe.py` |
| `r3_probe_log.txt` | `r3_probe.py`, `r3_dual_formula.py`, `r3_hull_dim_check.py` |

This is recorded because it is a real property of the evidence: three of the phase-2 logs cannot be
regenerated by running "the script" — they need two or three. Anyone re-running from the
`REPRODUCIBILITY.md` instructions without this knowledge would get a truncated log and might think
the evidence was incomplete.

## 4. Finding: `p3_quantum_table_log.txt` preserves a historical failure

That log opens with `numpy: ModuleNotFoundError: No module named 'numpy'` before the successful run.
It is the record of the environment regression that forced the numpy-free rewrite, kept in place on
purpose. The tool skips exactly that line and then requires the rest to match — so the failure stays
visible in the repository while not being mistaken for current behaviour.

Its CSV dump at the end is replaced by a stronger check: `QUANTUM_CODE_PARAMETER_TABLE.csv` is
snapshotted before the run and must be **byte-identical** afterwards. It is. Independently confirmed
by `git status`, which is clean after the full run — the 504-row table is not merely "the same 504
rows", it is the same file.

## 6. What this establishes, and what it does not

**Establishes:** the repository is internally reproducible at the level of "run the committed code,
get the committed output". No log is orphaned, no script was left in a state that no longer matches
its recorded evidence, and the largest deliverable (the 504-row CSV) is regenerated exactly.

**Does not establish:**

* **Correctness.** A script that reproduces a wrong number reproduces it faithfully. This audit is a
  drift check, not a proof. The correctness arguments are in the individual documents
  (`P3_1_TABLES.md`, `P3_3_RING_GRAY.md`, `P3_4_QUANTUM_DISTRIBUTION.md`,
  `CONSTITUENT_ENUMERATOR_FORMULA.md`, `P3_7B_L2_PROVENANCE_AUDIT.md`), and two of them rest on
  proofs, not on logs.
* **Novelty.** Nothing here bears on the literature question; blockers B-1, B-2a, B-2b and
  Tian–Gao–Gao remain open (`P3_8_BLOCKER_PROGRESS.md`).
* **That Phase 9 should be written.** It should not: reproducing a log is not a theorem. **The
  Phase 9 NO-GO decision is unchanged.**
* **Determinism across machines.** Only `PYTHONHASHSEED` is pinned. A different Python minor version
  could in principle reorder something; the two `pypdf`-dependent tools are excluded because they
  need a package that is absent from this environment (§7).

## 7. Probes deliberately not in the regression set

| `tools/extract_source_text.py`, `find_and_verify_source.py`, `inventory.py`, `verify_source_pdf.py` | acquisition/inventory tools bound to the network and to the source PDF; their output *is* the source tree, which `PHASE0_VERIFICATION_LOG.md` already pins by sha256 |
| `code/phase1_*.py` | Phase 1 regenerations; their outputs are quoted inside `phase1/*.md` rather than stored as separate logs |

Excluding them is stated rather than silent, and none of them carries a numerical claim that is not
re-verified elsewhere.
